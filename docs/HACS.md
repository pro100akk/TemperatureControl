# Публикация Apartment Comfort в GitHub и подключение HACS

## Текущий статус

Создан репозиторий [pro100akk/TemperatureControl](https://github.com/pro100akk/TemperatureControl), видимость **Private**, лицензия **MIT**. Подготовлены `hacs.json`, структура `custom_components`, проверки и публикация релиза через GitHub Actions. В `manifest.json` указаны адрес репозитория и сопровождающий `@pro100akk`.

Приватный репозиторий служит для разработки и хранения проекта. HACS не может его устанавливать; до отдельного решения владельца открыть доступ используется ручная установка. Никакие скрипты или workflows не меняют видимость репозитория автоматически.

## Однократная подготовка репозитория

1. Создать **закрытый** репозиторий GitHub `TemperatureControl`. Позднее, только по отдельному решению владельца, перевести его в публичный для HACS.
2. Включить Issues. Указать описание: `Adaptive apartment climate control for Home Assistant` и темы `home-assistant`, `hacs`, `custom-integration`, `climate`.
3. Заполнить настоящие метаданные (значения ниже — обозначения для замены):

   ```text
   python tools/configure_repository.py --repository OWNER/REPOSITORY --maintainer GITHUB_USERNAME
   ```

   Скрипт устанавливает `documentation`, `issue_tracker` и `codeowners` в манифесте. Аккаунт сопровождающего может отличаться от организации-владельца репозитория.

4. Загрузить файлы проекта в закрытый репозиторий, включая `.github/workflows`, `hacs.json`, `custom_components`, `tools`, `tests`, `LICENSE`, README и документацию. Не загружать `__pycache__`, виртуальную среду или `dist/` как исходники.
5. Проверить GitHub Actions → Validate. Проверка HACS пропускается для приватного репозитория; после открытия доступа запустить Validate повторно. Локальный запуск тестов не заменяет результат HACS validation на GitHub.
6. После успешных проверок создать и отправить тег `v0.1.0`. Workflow Release проверит совпадение версии, выполнит тесты и создаст GitHub Release с архивом для ручной установки.

Если GitHub Actions запрещены политикой аккаунта, релиз можно создать вручную на проверенном коммите. После открытия репозитория установка HACS из основной ветки работает без релиза; релизы нужны для удобного выбора версий. Релиз в закрытом репозитории тоже остаётся закрытым.

## Установка в Home Assistant

При уже установленном HACS откройте меню ⋮ → Custom repositories, добавьте URL созданного GitHub-репозитория и выберите Integration. Скачайте Apartment Comfort, перезапустите HA и добавьте интеграцию через «Устройства и службы».

При первой настройке оставьте режим наблюдения. Установка через HACS не включает управление приборами. Обновление уже существующей конфигурации сохраняет её параметры.

## Проверки и обновления

- `validate.yml`: локальные тесты, синтаксис Python, согласованность метаданных с репозиторием, воспроизводимость переводов, официальный HACS Action.
- Проверка `brands` пропускается для личного custom repository. Включение в общий каталог HACS и отправка брендинга в home-assistant/brands в эту задачу не входят.
- `release.yml`: запускается только при отправке тега `v*`, проверяет его совпадение с `manifest.version`, создаёт Release через стандартный токен GitHub Actions.
- Ни один workflow не подключается к домашнему HA и не управляет устройствами. Права записи выдаются только заданию создания релиза.
- Следующие версии должны изменять `manifest.version`; перед выпуском также обновляются сведения о версии в документации и устройстве.

Источники: [общие требования HACS](https://hacs.dev/docs/publish/start/), [структура интеграции](https://www.hacs.dev/docs/publish/integration/), [проверка GitHub Action](https://hacs.dev/docs/publish/action/).
