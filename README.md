# Apartment Comfort

Интеграция Home Assistant для управления температурой, прогноза её изменения и вентиляции помещения. Поддерживает радиаторное отопление, обдув радиатора, резервный тёплый пол, кондиционер и вытяжные вентиляторы. Один экземпляр интеграции обслуживает одну температурную зону.

Все настройки доступны через интерфейс Home Assistant. Для начала нужны только датчик комнатной температуры и сущность периода дня; остальные датчики и приборы подключаются по необходимости. Управление приборами по умолчанию отключено: интеграцию можно использовать для наблюдения и рекомендаций.

## Установка и обновление

Требуется Home Assistant 2025.12 или новее. Интеграция находится на раннем этапе развития; перед включением управления рекомендуется проверить показания и решения в режиме наблюдения.

### Через HACS

1. Откройте **HACS → ⋮ → Пользовательские репозитории**.
2. Добавьте `https://github.com/pro100akk/TemperatureControl` в категории **Интеграция**.
3. Найдите **Apartment Comfort** и установите последний опубликованный релиз.
4. Перезапустите Home Assistant.
5. Откройте **Настройки → Устройства и службы → Добавить интеграцию → Apartment Comfort**.

Для установки через HACS репозиторий должен быть публичным. При отсутствии доступа к нему используйте ручную установку из доступного релиза.

### Вручную

1. Откройте [страницу релизов](https://github.com/pro100akk/TemperatureControl/releases/latest) и скачайте архив `apartment_comfort-<версия>.zip`.
2. Скопируйте из архива каталог `custom_components/apartment_comfort` в `/config/custom_components/` Home Assistant.
3. Перезапустите Home Assistant и добавьте интеграцию через **Устройства и службы**.

Для обновления замените каталог интеграции файлами нового релиза и перезапустите Home Assistant. Повторно добавлять интеграцию не требуется. Версия релиза, манифеста, карточки устройства и диагностики согласованы. Для установки конкретной версии выбирайте релиз с номером вида `0.2.0`; основная ветка предназначена для разработки.

## Первоначальная настройка

1. Укажите название зоны, основной датчик температуры и сущность периода дня (`input_select`, `select` или `sensor`).
2. Выберите дополнительные датчики и доступные приборы. Неиспользуемые поля оставьте пустыми.
3. Сопоставьте состояния сущности периода с шестью периодами: утро, день, вечер, подготовка ко сну, ночь и перед пробуждением. Задайте целевую температуру для каждого периода.
4. Проверьте показания и рекомендации с выключенным параметром **«Управлять приборами»**.
5. Для автоматического управления включите этот параметр. Резервный тёплый пол и каждое вытяжное устройство разрешаются отдельно.

Если сущности периода нет, можно создать помощник **«Выпадающий список»** со значениями `morning`, `day`, `evening`, `pre_sleep`, `night`, `pre_wake`. Периоды переключаются отдельными автоматизациями Home Assistant или вручную. Встроенного расписания нет. Для постоянной температуры можно назначить одинаковую цель всем периодам.

После установки настройки доступны через **Apartment Comfort → Настроить**. Разделы датчиков, приборов, периодов и управления редактируются независимо. Чтобы убрать необязательный датчик или прибор, очистите соответствующее поле. Один управляемый прибор нельзя назначить нескольким ролям или зонам интеграции.

## Управление температурой

Виртуальный термостат поддерживает режимы **нагрев**, **охлаждение** и **выключено**. Режим выбирается пользователем. Временная уставка действует до смены периода; профиль `schedule` возвращает управление по периоду.

| Оборудование | Поддержка и поведение |
| --- | --- |
| Радиатор | Сущность `climate` с режимами `heat` и `off`. Основной источник нагрева. При необходимости уставка компенсирует разницу между датчиком термоголовки и комнатным датчиком, в пределах 10 °C. |
| Обдув радиатора | `fan`, `switch` или `light`. Работает при запросе нагрева и достаточной температуре радиатора. Можно выбрать контроль по поверхности или по трубе вместе с подтверждённым нагревом термоголовки. |
| Тёплый пол | `climate` с режимами `heat` и `off`. Резерв после заданной задержки при устойчивом дефиците температуры и подтверждённой недоступности отопления либо отсутствии настроенного радиатора. Время работы ограничено. |
| Кондиционер | `climate` с режимами `cool` и `off`. Соблюдается минимальная пауза между включениями. |

Обдув разрешается при температуре выбранного источника выше комнатной более чем на 2 °C. Для режима по трубе дополнительно требуется `hvac_action: heating`. Горячая труба сама по себе не подтверждает нагрев радиатора. Дневной и ночной пределы скорости настраиваются отдельно. Реле обдува поддерживает только включение и выключение; для запрета ночной работы задайте ночной предел 0 %.

По умолчанию открытое окно останавливает нагрев и охлаждение. Настройка **«Разрешить отопление при открытом окне»** позволяет продолжать нагрев; охлаждение остаётся заблокированным. Неизвестное состояние выбранного датчика окна блокирует температурное управление. Без датчика окно считается закрытым, а автоматический запуск кухонной вытяжки недоступен.

### Выбор регулятора

| Регулятор | Принцип | Особенности |
| --- | --- | --- |
| Гистерезис | Включение при заданном отклонении от цели, выключение при достижении цели. | Простая настройка, запрос нагрева или охлаждения 0/100 %. |
| PI | Учитывает текущую ошибку температуры и её длительность. | Плавный запрос 0–100 %, помогает уменьшать длительное отклонение от цели. Настраиваются Kp и Ki. |
| PID | Добавляет к PI фильтрованную скорость изменения измеренной температуры. | Может раньше уменьшать запрос при быстром приближении к цели. Дополнительно настраивается Kd; чувствительнее к шуму датчика. |

PI/PID изменяет уставку климатического прибора в заданных пределах и запрос скорости обдува. Процент запроса не является измеренной мощностью или положением клапана. Штатный термостат прибора продолжает работать. Интеграл ограничен; смена режима, цели и блокировки сбрасывают накопление. Для всех регуляторов действуют ограничения окна, пола, кондиционера и обдува. Автоматического подбора Kp/Ki/Kd нет.

## Вентиляция и качество воздуха

Дополнительно можно подключить CO₂, влажность помещения и ванной, уличную температуру и влажность, а также бинарный признак приготовления пищи. На их основе формируются рекомендации открыть окно, продолжить или завершить проветривание. Для осушения сравнивается абсолютная влажность внутри и снаружи; наружная относительная влажность сама по себе не определяет эффективность проветривания.

Кухонная вытяжка и вентилятор ванной поддерживают сущности `fan`, `switch` и `light`. Их управление включается отдельно:

- **Вентилятор ванной** включается по верхнему порогу влажности и выключается по нижнему. Закрытое окно не запрещает удаление влажного воздуха из ванной.
- **Кухонная вытяжка** запрашивается при повышенном CO₂, приготовлении пищи, возможности осушения или охлаждения наружным воздухом. Автоматический запуск требует подтверждённо открытого окна, известного периода и температуры выше минимума проветривания.
- Перед сном, ночью и перед пробуждением кухонная вытяжка по умолчанию запрещена. Можно разрешить работу с отдельным пределом воздухообмена. Периоды определяются настроенной сущностью Home Assistant.
- Реле не запускается ночью, если требуемый предел ниже полной производительности: уменьшить скорость реле не может. Днём положительный запрос для реле означает полное включение.

Интеграция не открывает и не закрывает окна. Уведомления можно настроить отдельными автоматизациями по сенсору рекомендаций.

### Скорость вытяжки и диммер

Для вентилятора с регулировкой скорости используется процент скорости, для совместимого `light`-диммера — процент яркости. Положение регулятора может нелинейно влиять на воздухообмен.

Параметр **«Калибровка команда:воздухообмен»** задаёт возрастающие пары от `0:0` до `100:100`. Пример: `0:0,25:10,50:35,75:65,100:100`. Здесь команда 50 % соответствует 35 % относительного воздухообмена. Интеграция интерполирует значения и рассчитывает обратное преобразование для отправки команды.

Начальная кривая является примером. Настройте её по характеристикам или измерениям оборудования. Она описывает воздухообмен, а не электрическую мощность. Диммер должен быть совместим с двигателем и обеспечивать устойчивый запуск на используемых уровнях.

### Ручное управление и другие автоматизации

Уже работающие внешние приборы интеграция не присваивает. Изменение состояния или скорости вытяжного устройства вручную либо сторонней автоматизацией передаёт этот прибор внешнему управлению до выбора профиля `schedule`. Передача сохраняется после перезапуска; температурный регулятор и прогноз продолжают работать. Список таких приборов доступен в атрибуте `exhaust_holds`.

Собственные команды различаются по контексту Home Assistant. Если устройство не сохраняет контекст, изменение может быть консервативно принято за внешнее управление. Команду, не изменившую наблюдаемое состояние, определить невозможно.

Для радиатора, пола, кондиционера и обдува радиатора действует общий режим паузы после распознанного ручного изменения через Home Assistant. Его снимает профиль `schedule` или выбор режима виртуального термостата. Конкурирующие автоматизации этих климатических приборов следует отключить.

## Прогноз температуры и погода

Прогноз рассчитывается при наличии актуальной комнатной температуры, включая открытое окно, работающую вентиляцию, наблюдение и выключенное обучение. Горизонт настраивается от 5 до 60 минут.

- **`ready`** — накоплено достаточно наблюдений текущего режима, ошибка модели и наружные условия находятся в допустимых пределах.
- **`estimated`** — предварительная оценка по ограниченной статистике или начальной модели теплообмена. Её точность зависит от помещения и настроек.
- Без актуальной комнатной температуры прогноз недоступен. При отсутствии наружных данных и подтверждённых источников тепла начальная оценка сохраняет текущую комнатную температуру.

Обучение разделяет режимы по фактической работе приборов, окну, воздухообмену вытяжки, приготовлению пищи и погодным условиям. Используются устойчивые участки от пяти минут; неизвестные состояния, длительные пропуски и резкие скачки не используются. Для статуса `ready` требуется не менее 12 наблюдений, средняя ошибка скорости не выше 1,5 °C/ч и наружная температура в пределах 3 °C от обученных условий. Коэффициенты сохраняются между перезапусками.

Начальная модель предполагает, что закрытое окно существенно ограничивает приток наружного воздуха: вытяжные устройства при этом не добавляют прямой наружный теплообмен. Это приближение может не подходить помещениям с отдельными приточными каналами. При открытом окне применяются настраиваемые коэффициенты теплообмена окна и вытяжки. По мере накопления наблюдений используются обученные суммарные скорости изменения температуры.

### Источники погодных данных

Необязательная сущность `weather` добавляет текущие погодные условия и почасовой прогноз. Актуальные уличные датчики температуры и влажности имеют независимый приоритет; отсутствующие или устаревшие показания заменяются доступными текущими данными погоды.

Для будущей температуры используется изменение относительно текущей температуры **того же погодного источника**. Например, повышение прогноза на 2 °C применяется как динамика +2 °C независимо от расхождения погодной температуры с уличным датчиком. На выбранном горизонте используется интерполяция, а влияние на комнату зависит от коэффициента теплообмена. Почасовой прогноз обновляется раз в 30 минут. Если источник не поддерживает его или данных недостаточно, прогноз комнаты продолжается без погодной динамики.

Прогноз предполагает сохранение состояния приборов. Он информационный: не предсказывает будущие переключения расписания и не меняет команды температурного регулятора. Присутствие и мощность компьютера при подключении отображаются в диагностике, но не корректируют уставку.

## Диагностика

Интеграция создаёт виртуальный термостат и семь сенсоров: состояние контроллера, рекомендация по проветриванию, целевая температура, прогноз температуры, запрошенная мощность, состояние прогноза и состояние обдува радиатора.

Атрибуты показывают входные данные, причины решений, параметры прогноза и ошибки управления. Поддерживаются русский и английский интерфейсы и скачивание диагностики. Запрос нагрева в решении контроллера не подтверждает фактическую работу прибора: она определяется по доступным данным устройства.
